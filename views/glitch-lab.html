📖 Researcher's Guide: Tokenizer Smuggling

Description: Tokenizer smuggling exploits the difference between how **Guardrails** (which often look at raw strings) and **LLMs** (which look at integer tokens) perceive text. By injecting non-printing characters or using "Glitch Tokens"—tokens that the model's tokenizer creates but its training data rarely included—an attacker can bypass security filters while keeping the instruction meaningful to the LLM.

🧪 How to Test:
  1. Identify a blocked keyword (e.g., "SYSTEM").
  2. Use the **ZWJ Injection** technique to turn "SYSTEM" into "S‍Y‍S‍T‍E‍M".
  3. Observe if the guardrail fails to flag the word while the model still follows the instruction.
  4. Test **Glitch Tokens** (like "SolidGoldMagikarp") to see if the model produces nonsensical or unintended administrative behavior.
🛡️ How to Fix (Mitigation):
  • Normalize Input: Always run Unicode normalization (NFKC) and strip non-printing characters *before* passing text to the guardrail.
  • Token-Level Guardrails: Apply security filters to the **output of the tokenizer** (integer IDs), not just the raw input string.
  • Sanitize Glitch Tokens: Explicitly block or re-map known glitch tokens in the tokenizer configuration.
  • Visual Encoders: Use VLMs to "look" at the text as a human would, detecting hidden joiners.
