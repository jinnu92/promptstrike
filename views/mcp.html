📖 Researcher's Guide: Understanding MCP Protocol Hijacking

What is MCP?
The Model Context Protocol (MCP) is an open standard that enables AI models to connect to external "tools" and "data sources" (like Google Drive, GitHub, or local SQL databases) through a standardized JSON-RPC server.

The Vulnerability: Protocol-Level Injection
When an AI model uses MCP, it reads the Tool Schema (JSON descriptions of what a tool does) to decide which tool to call. An attacker can inject malicious instructions directly into these descriptions (Schema Poisoning) or use a tool that interacts with internal networks (SSRF) to bypass traditional firewalls.

🧪 How to Test:
  1. Identify: Find an application using MCP (e.g., Claude Desktop with MCP plugins, Cursor IDE with MCP tools).
  2. Poison: Create a malicious tool schema using this module that includes hidden directives in the description or inputSchema.
  3. Deploy: Add your malicious tool to the MCP server configuration.
  4. Verify: Observe if the AI agent executes unauthorized commands, such as exfiltrating data or making SSRF calls to internal APIs (e.g., http://localhost:8080/admin).
🛡️ How to Mitigate:
  • Schema Validation: Use strict regex patterns to ensure that tool descriptions and parameter names do not contain "Instruction-like" keywords (e.g., "Ignore," "System," "Instead").
  • Network Sandboxing: Run MCP servers in isolated containers with zero access to internal localhost services unless explicitly required.
  • Least Privilege: Only grant the AI agent access to the specific tools it needs for a task, rather than all available MCP tools.
  • Call Inspection: Implement an "Interceptor" that analyzes the JSON-RPC calls generated by the model before they reach the MCP server to catch malicious parameter injections.
